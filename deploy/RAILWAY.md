# Deploying Convene to Railway

Total time first run: ~30 minutes. Costs ~$10–15/mo for hosting + DB at this app's
v1 traffic, plus whatever Anthropic spends (hard-capped to $50/mo by the code).

You'll end up with three kinds of services in one Railway project:

1. **web** — the Next.js app, built from this repo's `Dockerfile`.
2. **postgres** — Railway-managed Postgres.
3. **cron-** × 6 — tiny `alpine + curl` services, one per `/api/cron/*` route, each on its own schedule.

---

## 0. Prerequisites

- A GitHub account with this repo pushed to it (public or private, both work).
- A credit card. Railway's free trial gives you $5 credit. After that the **Hobby plan is $5/mo + usage** (~$5–10/mo for this app at v1 scale).
- Accounts for the four free-tier providers we use:
  - **Resend** — sign up at resend.com, verify your sending domain (15 min including DNS).
  - **Anthropic** — console.anthropic.com, top up $20 minimum, copy a key.
  - **Mapbox** — account.mapbox.com, copy the default public token.
  - **Cloudflare R2** — create an R2 bucket named `convene`, generate an S3 API token, note the account ID + access key + secret. Set up a public hostname (R2 → Settings → Public Access → connect a domain or use the auto r2.dev URL for dev).
- A domain (cheapest: Cloudflare Registrar, ~$10/yr).

If you skip any of the four providers above, the corresponding feature degrades gracefully but doesn't crash — e.g. no Mapbox token = map page shows a placeholder.

## 2. Create the project + Postgres

1. Go to https://railway.com/new.
2. Click **Empty Project**. Name it `convene`.
3. Inside the project, click **+ New → Database → Add PostgreSQL**.
   - Railway provisions a managed Postgres in ~20 seconds.
   - Click the service tile → **Variables** tab. Note that `DATABASE_URL` (and a few others) appear here. You don't need to copy them — they're referenceable from other services via `${{Postgres.DATABASE_URL}}` syntax.

---

## 3. Deploy the web service

### Option A — from GitHub (recommended)

1. **+ New → GitHub Repo → connect** your GitHub account → pick the `convene` repo.
2. Railway sees `Dockerfile` and `railway.json` and starts a build immediately. The first build takes ~3 minutes (Prisma + Next compile).
3. Rename the service from the autogenerated name to `web` (top of the service tile → settings icon → Service Name).

### Option B — from CLI in this directory

```bash
railway link            # pick your "convene" project
railway up              # uploads the repo and triggers a build
```

### Set the web service's environment variables

Open the **web** service → **Variables** tab → **Raw Editor**. Paste the following, replacing the right-hand sides with your real values:

```
# Postgres — reference the sibling service
DATABASE_URL=${{Postgres.DATABASE_URL}}

# Auth.js
AUTH_SECRET=                 # generate: openssl rand -base64 32
AUTH_URL=https://your-domain.com
AUTH_TRUST_HOST=true

# Email (Resend)
RESEND_API_KEY=re_xxxxxxxx
EMAIL_FROM=Convene <noreply@your-domain.com>

# Anthropic
ANTHROPIC_API_KEY=sk-ant-xxxxxxxx

# Mapbox
MAPBOX_TOKEN=pk.xxxxxxxx
NEXT_PUBLIC_MAPBOX_TOKEN=pk.xxxxxxxx

# Cloudflare R2
R2_ACCOUNT_ID=xxxxxxxx
R2_ACCESS_KEY_ID=xxxxxxxx
R2_SECRET_ACCESS_KEY=xxxxxxxx
R2_BUCKET=convene
R2_PUBLIC_URL=https://files.your-domain.com

# Cron auth (shared with the cron services in step 5)
CRON_SECRET=                 # generate: openssl rand -hex 32

# Scene defaults
DEFAULT_TIMEZONE=America/Denver
DEFAULT_MAP_CENTER_LAT=35.0844
DEFAULT_MAP_CENTER_LNG=-106.6504

# LLM cost guard
LLM_DAILY_LIMIT_PER_USER=50
LLM_MONTHLY_BUDGET_USD=50
```

Save. Railway auto-redeploys.

### First deploy notes

- `railway.json`'s `startCommand` is `npx prisma migrate deploy && node server.js`. The migrate happens on every restart, which is idempotent — it only applies pending migrations.
- The first deploy will fail if you haven't generated any migrations locally. Run this once on your dev machine and commit the result:

  ```bash
  # in this repo, against a local Postgres (or against the Railway DB via railway run):
  npx prisma migrate dev --name initial
  git add prisma/migrations
  git commit -m "Initial Prisma migration"
  git push
  ```

- If you already have data + need to seed the convention calendar:

  ```bash
  railway run --service web npm run prisma:seed
  ```

### Public URL & custom domain

1. **Settings → Networking → Public Networking** → click **Generate Domain** to get a `*.up.railway.app` URL. Verify the app loads.
2. **Settings → Networking → Custom Domain** → enter your domain, copy the CNAME, add it to your DNS provider. SSL provisions in ~1 minute.
3. **Important:** update the `AUTH_URL` var (and `EMAIL_FROM`'s domain) to the custom URL once DNS resolves. Redeploy.

- **R2 public hostname** — Cloudflare → R2 → bucket settings → Public Access → Connect Custom Domain. Set `R2_PUBLIC_URL` to that hostname.

## 5. Create the six cron services

Convene has six cron routes. Each one is its own Railway service so individual failures don't cascade. They share the `deploy/cron.Dockerfile` image and differ only in `CRON_PATH` and schedule.

For **each** of the six entries in the table below:

1. In the project, click **+ New → Empty Service**.
2. Service name: use the name in the table (e.g. `cron-soft-claims`).
3. **Settings → Source → Connect Repo** → pick `convene` repo.
4. **Settings → Build → Dockerfile Path** → `deploy/cron.Dockerfile`.
5. **Settings → Build → Build Context** → `deploy/` (so the script + Dockerfile live next to each other inside the build).
6. **Settings → Deploy → Cron Schedule** → paste the cron expression from the table.
7. **Variables**:
   ```
   WEB_URL=${{web.RAILWAY_PUBLIC_DOMAIN}}     # or hardcode https://your-domain.com
   CRON_SECRET=${{web.CRON_SECRET}}           # reuse the web service's value
   CRON_PATH=<from the table>
   ```
8. **Settings → Deploy → Healthcheck** — leave blank (cron services are one-shot).
9. **Deploy**. The first run executes immediately; subsequent runs fire on schedule.

| Service name              | `CRON_PATH`                                  | Schedule                  | Purpose                                       |
|---------------------------|----------------------------------------------|---------------------------|-----------------------------------------------|
| `cron-soft-claims`        | `/api/cron/expire-soft-claims`               | `0 * * * *`               | Hourly — purge expired soft-claims (§6.3).    |
| `cron-tentative-events`   | `/api/cron/expire-tentative-events`          | `0 3 * * *`               | Daily 03:00 UTC — auto-cancel stale TENTATIVE.|
| `cron-compute-overlap`    | `/api/cron/compute-overlap`                  | `0 4 * * *`               | Daily 04:00 UTC — attendance overlap (§9.4).  |
| `cron-weekly-digest`      | `/api/cron/weekly-digest`                    | `0 16 * * 4`              | Thursday 16:00 UTC — weekly digest (§11.3).   |
| `cron-hard-delete`        | `/api/cron/hard-delete-grace-expired`        | `0 5 * * *`               | Daily 05:00 UTC — finalize account deletions. |
| `cron-report-notify`      | `/api/cron/report-notify-subjects`           | `0 * * * *`               | Hourly — 48h subject notification (§8.7).     |

You can verify by clicking a cron service → **Deployments** → look at the most recent run's logs. You should see something like:

```
[cron] 2026-05-21T16:00:00Z → https://your-domain.com/api/cron/weekly-digest
{"sent":42}
[cron] HTTP 200
```

## 6. Migrate & seed the database

If you didn't already commit the initial migration in step 3:

```bash
# From your dev machine, against the Railway DB:
railway link
railway run --service web npx prisma migrate deploy
railway run --service web npm run prisma:seed
```

The seed installs the 2026 convention calendar (Anthrocon, MFF, FWA, etc.) used by conflict detection.

To make yourself the first admin: sign up via the magic-link flow, then run:

```bash
railway run --service web sh -c "echo \"
  UPDATE \\\"User\\\" SET \\\"displayName\\\" = 'You' WHERE email = 'you@example.com';
\" | npx prisma db execute --stdin --schema=prisma/schema.prisma"
```

Or just open Railway's **Postgres → Data** tab and edit the row inline.

## 7. Watching costs

Railway bills by metered usage. Three signals to watch in the first week:

1. **Project Usage tab** — total $ for the cycle. Hobby plan includes $5 of credit; you pay only above that. v1 traffic typically lands $3–8/mo.
2. **Anthropic dashboard** — your $50/mo cap. The app enforces 50 LLM calls/day/user via `LLMRateLimit`, but you should still alarm at Anthropic if you exceed $30/mo for a few days in a row.
3. **Cloudflare R2** — free up to 10 GB. With evidence uploads capped to 10 MB × 5 per report you'd need thousands of reports to overflow.

To cut Railway cost further:
- Set **Settings → Deploy → Replicas → 1** on the web service (default already).
- Set **Settings → Resources → Memory → 512 MB** on the web service (down from 1 GB default). Convene's resident set is ~200 MB.
- Cron services use ~$0.02 each per month combined; ignore.

## 8. After deploy: smoke test

1. Hit `/` — should show the marketing-lite or For You feed depending on whether you're signed in.
2. `/login` → enter email → check Resend dashboard for the magic link → click → land on `/onboarding`.
3. Create a group at `/groups/new`. Create an event. Visit `/calendar` and confirm it shows.
4. Open the calendar in two browser tabs. Edit the event from one. After ≤15 seconds the other tab refreshes itself.
5. `/api/ical/public` should return a `text/calendar` body.
6. Trigger a cron manually: in the cron service's **Deployments** → **Redeploy** → check logs return HTTP 200.

If anything 401s on the cron run, you've got a `CRON_SECRET` mismatch between the web service and the cron service. The `${{web.CRON_SECRET}}` reference variable handles this for you if you set both before deploying — but if you set them out of order, paste the same hex string into both manually.

---

## 9. Updating

`git push` to the connected branch redeploys the web service automatically. Crons inherit the image change next time they fire. Migrations run on every web container start, so:

```bash
git add prisma/migrations/<new-migration-folder>
git commit -m "..."
git push
```

is the full deploy procedure for a schema change.

---

## 10. Backups (optional but recommended)

Railway Postgres backups are a paid add-on. For v1, take nightly logical backups to R2 from a cron:

1. Add one more cron service called `cron-backup`.
2. Use a custom Dockerfile (in `deploy/`) that bundles `pg_dump` + the AWS CLI, or use the official `postgres:16-alpine` image with `awscli` apk-added.
3. Schedule: `0 6 * * *`.
4. Start command: `pg_dump $DATABASE_URL | gzip | aws s3 cp - s3://$R2_BUCKET/backups/$(date -u +%F).sql.gz --endpoint-url https://$R2_ACCOUNT_ID.r2.cloudflarestorage.com`
5. Env: `DATABASE_URL=${{Postgres.DATABASE_URL}}`, R2 creds.

I'd add this only after the app has real data worth backing up.

## Troubleshooting

| Symptom                                                | Likely cause                                                      |
|--------------------------------------------------------|-------------------------------------------------------------------|
| Build fails at `npx prisma generate`                   | Missing `node_modules/@prisma/client` in `.dockerignore` — fixed. |
| Web service crashloops with `P1001` Postgres error     | `DATABASE_URL` not referencing `${{Postgres.DATABASE_URL}}`.      |
| Magic links never arrive                                | Resend domain not verified, or `EMAIL_FROM` domain ≠ verified.    |
| 401 on every cron run                                  | `CRON_SECRET` mismatch between web service and cron service.      |
| Map page shows placeholder text                        | `NEXT_PUBLIC_MAPBOX_TOKEN` missing; it must be a `pk.…` token.    |
| `Uploader` returns "Sign failed"                       | R2 creds wrong, or bucket name mismatch.                          |
| Pages flicker / log `Error: Dynamic server usage`     | Normal — every page in this app is `ƒ (Dynamic)` by design.       |

For anything else, the web service's **Logs** tab is your friend. The standalone server logs every request.
